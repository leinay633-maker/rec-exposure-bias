### 1.1 问题

- **主问题**：语义 ID 生成式召回和 SASRec、双塔之间的差距，从“按曝光量加权的有偏测试”换到“稠密测试”时会不会变。两份测试是同一批用户、同一份推荐列表、同一份标签，只差每个正样本占多少权重。统计量和研究一相同：D = Δ稠密 − Δ有偏。
- **次问题**：
  1. 稠密测试上的直接比较。
  2. 语义有没有用：文本语义 ID 对打乱后的语义 ID。
  3. 按热度分组，尤其训练期一次曝光都没有的冷门视频。
  4. 更接近真实日志的有偏测试（借用其他用户 5 天的曝光集合）和自然稀疏测试（大矩阵 9/01–9/05，另一批用户）上的结果。

### 1.2 能识别什么

- **有偏测试只模拟非个性化的热度删失**：固定每个模型的推荐列表，只改变哪些正样本算数、各占多少权重，看模型之间的差距跟着变多少。它不模拟旧策略按个人兴趣挑视频带来的偏差。所有模型都在同一份有偏的大矩阵上训练，训练数据带来的偏差不在这个比较里。
- **借用曝光集合的版本**保留了真实 5 天日志里一个用户看到的候选池视频有多少、哪些会一起出现（去重后的集合，不是曝光行数），但用的是别人的曝光，仍不是这个用户自己的。
- **小矩阵不是纯随机曝光**：快手先挑出彼此看过很多的用户和视频，再把没看过的（用户，视频）对在 15 天里插进推荐流补齐（KuaiRec 论文 §3.1.1）；约 0.4% 的对因为用户拉黑了作者而缺失。它回答的是“几乎每一对都有标签时”模型排得准不准，不是“随机推荐时”的反应。
- **时间**：小矩阵和大矩阵采集于同一段时间（2020-07-05 至 09-05），部分小矩阵标签早于 8/10 的训练历史。稠密测试是同期矩阵的补全，不是预测未来。
- **文本**：视频文本 2024-06 发布，采集时点不明，可能晚于日志。
- **小矩阵用户的训练数据只有池外视频**：大矩阵里挖掉了“小矩阵用户 × 候选池视频”整块（DATA §3），模型要从用户看过的池外视频推断他对池内视频的偏好。这是数据集的构造，所有模型相同。
- 生成式召回在这里是本机规模的小模型复现（TIGER 式），不代表工业规模的效果。
- 区间只反映用户抽样的不确定性，条件于训练出来的 3 个种子和固定的模拟方案。
- 未检出不说成“一致”或“没有差别”；不说首次；不写线上效果。

### 1.3 定位

- Parajuli 等（RecSys 2026，arXiv 2607.25097）在 KuaiRec 上用 LensKit 的 123 个配置发现，大矩阵上的各种稀疏评测设计给出的模型排序，和小矩阵上稠密评测的排序负相关（Kendall τ −0.59 到 −0.17）。本研究换成序列模型和语义 ID 生成式召回，用同一批用户、同一份推荐列表构造有偏测试，把“正样本按曝光量计权”这一项单独拿出来检验。
- 在 KuaiRec 上评测过语义 ID 生成式召回的论文（arXiv 2602.05663、2605.14853、2608.21012、2608.17613）都在单个矩阵内按时间留出；检索到的范围内没有用小矩阵做稠密测试的。检索不穷尽，不说首次。

## 2. 数据与切分

- 来源、校验、总数和关系见 `docs/kuairec/DATA.md`。
- **去重**：大矩阵先去掉整行完全相同的行，再把（用户、视频、时间戳）相同但其他列不同的整组删掉（DATA §4）。重复行的时间戳相同、日期也相同，所以封存窗口内外可以各自去重。小矩阵没有重复。
- **标签**：`watch_ratio` > 2.0 为正样本（KuaiRec 论文 §3.1.3 和 README 的定义），否则为负。
- **大矩阵的窗口**（日期含两端）：

| 用途 | 日期 | 说明 |
| --- | --- | --- |
| 训练 | 7/05–8/10 | 实际有数据的是 7/05–7/12、8/01–8/10 |
| 验证 | 8/27–8/31 | 调参、早停，以及 §2.2 借用曝光集合 |
| 自然测试（封存） | 9/01–9/05 | 次问题 4 |

- **用户**：小矩阵的 1,411 个用户，以下称小矩阵用户；大矩阵其余 5,765 个用户，以下称其他用户。
- **代理和测试用户**：小矩阵用户里训练窗口至少有一个正样本事件的（审计数 1,401 人）按用户编号升序排好，取 `numpy.random.default_rng(20261101).choice(这些用户, size=round(0.2 × 人数), replace=False)` 作代理用户（280 人），其余作测试用户（1,121 人）。代理用户的小矩阵数据在冻结前可用，作代理试跑和功效检查；测试用户的小矩阵数据封存。没有正样本事件的 10 个小矩阵用户不进任何评测，他们的小矩阵行在打开前也不读。
- **候选池**：小矩阵的 3,327 个视频，按视频编号升序。
- **曝光量**：视频 i 的曝光量 w_i = 训练窗口里其他用户对它的行数（去重后）。候选池里 w = 0 的视频（审计数 555 个）称冷门组；其余按（曝光量，视频编号）升序等分 4 组（`numpy.array_split`），记为 1–4 组，第 4 组最热。

### 2.1 正样本事件和历史

- **正样本事件**：训练窗口里标签为正的行，按（用户，时间戳，视频编号）排序，同一用户同一视频只留第一次。
- **历史**：用户最近的 L = 50 个正样本事件里的视频（全部视频，不只候选池），按时间先后、左侧补空位。所有评测都用这一份历史，不加入验证或测试窗口的行。没有正样本事件的用户不进任何评测。

### 2.2 每类评测的候选、目标和人群

每个模型对每个用户只产生一份前 100 的推荐列表，只在下面规定的候选里排；同一个用户的稠密、有偏、借用三种指标都用这同一份列表。

- **自然评测**（验证、自然测试，其他用户）：候选 = 候选池去掉该用户训练窗口里有过任意一行的视频；目标 = 窗口里该用户标签为正的候选视频。人群 = 至少一个目标、至少一个正样本事件的用户。
- **稠密测试**（代理或测试用户）：候选 = 该用户在小矩阵里有行的候选池视频（缺失的约 0.4% 不排）；目标 T_u = 其中标签为正的视频。
- **有偏测试**（主分析用）：同一份候选和目标，但每个目标按曝光量计权。Recall_w@K(u) = Σ_{i∈T_u∩前K} w_i / Σ_{i∈T_u} w_i。
  - 含义：若测试日志的曝光行按 w_i 的比例独立抽取、标签固定、重复曝光照计，Recall_w 是“正样本曝光行的召回”的大样本极限；它不是有限窗口里按去重视频算的召回的精确期望。曝光行数在这里只是曝光强度的代理。它是确定性的，不需要随机抽样。
  - 权重全部等于同一个正数时，Recall_w 恰好等于稠密测试的召回，所以不再单设均匀抽样对照。
- **借用曝光集合**（敏感性分析）：供体 = 验证窗口里在候选池视频上至少有一行的其他用户，按用户编号升序。第 r 次（r = 0…19）用 `numpy.random.default_rng([20261101, 100 + r]).integers(0, 供体数, size=1411)` 给按用户编号升序的全部小矩阵用户各配一个供体（有放回）；观测集合 = 供体在验证窗口里有过行的候选池视频；目标 = T_u ∩ 观测集合。只算有至少一个目标的那几次（记为 m_u 次），每次用二值增益算指标，取这几次的平均。这是“条件于目标非空”的供体混合，人群也取决于这 20 次分配。
- **人群**：
  - H1、H2 和有偏测试：测试用户里 T_u 非空、且 Σ_{i∈T_u} w_i > 0 的。
  - H3 和其他只用稠密测试的分析：测试用户里 T_u 非空的。
  - 借用曝光集合：H1 人群里 m_u ≥ 1 的；它的 D 的稠密一端也在这批人上重算。报告它和 H1 人群的人数差、每人目标数的分布。
  - 自然测试：另一批用户，单独重抽样。
  - 每份分析都报告人群人数和被排除的人数。

## 3. 模型组

五个模型。按两个维度排：SASRec 和打乱语义 ID 不用视频内容，双塔和文本语义 ID 用同一份文本向量；两个语义 ID 模型是生成式，SASRec 和双塔是打分式。热度作参照。

### 3.1 共同设置

- 视频编号覆盖大矩阵全部 10,728 个视频，历史长度 L = 50。
- **训练对**：按用户编号升序，把每个用户的正样本事件从末尾往前依次切成长 L + 1 的窗口（最新的窗口在前），相邻窗口重叠一个事件，最早的窗口左侧补空位。窗口里第 j 个事件（j ≥ 2）是一个目标，上文是窗口里它之前的事件。所以除每个用户的第一个事件外，每个事件恰好作一次目标。四个可学的模型都用这同一批（上文，目标）对；双塔按窗口顺序、窗内位置从左到右展开成行。
  - 例：某用户有 3 个事件 a、b、c，只有一个窗口，前 48 位为空。SASRec 的输入是“48 个空位、a、b”，在 a、b 的位置分别预测 b、c；生成模型的输入是 192 个空 token 加上 a 的 4 个 token、b 的 4 个 token、c 的前 3 个 token，预测 b、c 各 4 个 token，a 只作输入；双塔得到两行（上文 a → 目标 b，上文 a、b → 目标 c）。
- **Transformer**（SASRec 和生成模型共用一份实现）：pre-norm，GELU，前馈层宽 4 倍隐维，可学的位置向量；注意力里空位不作 key，每个位置都能看到自己。dropout 用在输入嵌入之后、注意力权重上、以及每个子层输出加回残差之前；最后一层之后再过一次 LayerNorm。
- **初始化**：构造模型前调 `torch.manual_seed(s)`；模块按默认方式构造后，再按 `modules()` 的顺序把所有嵌入表重新按 N(0, 0.02²) 初始化（空位那行置零），线性层保留 PyTorch 默认初始化。
- **优化**：AdamW（β 0.9/0.999，ε 1e-8，weight decay 0）；前 200 步学习率从设定值的 1/200 线性升到设定值，之后不变；梯度范数裁到 1.0。训练开始前建一个 `torch.Generator().manual_seed(s)`，每个 epoch 用它调一次 `torch.randperm` 打乱训练对或窗口（跨 epoch 连续推进，不重置），最后不满一批的也训练。fp32 计算，允许 TF32 矩阵乘。
- **损失的平均**：SASRec 和双塔按目标数平均；生成模型按目标 token 数平均（每个目标 4 个）。
- **早停**：每个 epoch 结束在验证子集上算 Recall@100。取最好的 epoch（并列取较早的），连续 3 个 epoch 不超过最好值就停。
- **验证子集**：验证人群（审计后的缓存数 5,183 人）按用户编号升序，取 `numpy.random.default_rng(1).choice(这些用户, size=2000, replace=False)`，再按编号升序。调参的选择和早停都只看这 2,000 人。
- **并列**：配置的验证指标并列取网格里靠前的（§3.7 表里先列的因子变得最慢）；打分并列按视频编号升序；束搜索的得分并列按码的字典序。
- **失败**：
  - 训练报错或损失变成 NaN 的运行登记为失败，同一配置、同一种子从头重跑一次。调参（种子 0）的配置两次都失败就不参加选择；一个模型的配置全部失败，或选定配置的种子 1、2 两次都失败，就停下，在协议末尾追加处理办法后再继续。
  - 显存不足先于上面的规则处理：批大小减半、学习率不变、从头重训（新的一次运行），最少到窗口 16 个、双塔 128 行；最小批仍放不下就停下，追加处理办法。减批情况写进冻结一节。

### 3.2 热度

- 按训练窗口里对该视频有正样本事件的用户数排序，同数按视频编号升序。不调参，没有种子。

### 3.3 logQ 双塔（带文本）

- **编号向量表**：用户塔和视频塔共用，维数 d_e 见网格。
- **用户塔**：上文视频的编号向量取平均 → Linear(d_e, 256) → ReLU → Linear(256, 64) → L2 归一化。
- **视频塔**：编号向量、一级类目向量（`first_level_category_id`，UNKNOWN 单独一类，维数 d_e）、文本向量（§3.5 的 1,024 维，冻结）经 Linear(1024, d_e) 投影，三者拼接 → Linear(3d_e, 256) → ReLU → Linear(256, 64) → L2 归一化。
- **训练**：§3.1 的训练对，批大小 1,024。批内 softmax，温度 0.1。logQ 校正：训练时 logit 减去 log q_i，q_i = 视频 i 作为目标的次数 / 训练对总数；推理时不减。同一批里视频相同的行、同一用户的其他行不当负样本。最多 20 个 epoch。
- 温度固定为 0.1：研究一 RESULTS §8 里开 logQ 后换温度的影响不到 0.01。

### 3.4 SASRec

- 编号向量乘 √d 加位置向量，dropout 后进 2 层、2 头的 Transformer，取最后一位的输出和编号向量表做点积（输入输出共用一张表）。
- **训练**：§3.1 的窗口，每个目标位置对全部 10,728 个视频做 softmax 交叉熵。批大小 128 个窗口，学习率 1e-3，最多 40 个 epoch。
- 只用编号，不用文本和类目。

### 3.5 文本语义 ID 生成式召回

- **文本**：每个视频的标题、人工封面文字、话题标签和三级类目路径拼成一段（`genrec/text.py` 的 `describe`）；4 条记录按 DATA §1 修复。
- **编码器**：Qwen3-Embedding-0.6B，Hugging Face 提交 `97b0c614be4d77ee51c0cef4e5f07c00f9eb65b3`，只下载 safetensors，不运行仓库里的代码。文档侧不加指令，最长 256 个 token，左填充，取最后一个 token 的隐状态，L2 归一化，1,024 维；GPU 上 float16 推理。全部 10,728 个视频只编一次，结果存缓存并记哈希。
- **RQ-VAE**：
  - 结构：编码器 1024 → 512 → 256 → 128 → 32，解码器对称，层间 ReLU；3 层残差量化，每层 64 个码字，按欧氏距离取最近码字。
  - 损失（对维度求和、对视频取平均）：‖x − x̂‖² + Σ_l (‖sg(r_l) − e_l‖² + 0.25 ‖r_l − sg(e_l)‖²)，r_l 是第 l 层的残差，e_l 是选中的码字，解码器输入用直通估计。
  - 训练：`torch.manual_seed(s)` 初始化权重；另建一个 `torch.Generator().manual_seed(s)`，k-means 初始化和死码重置依次共用它。每层码本按层的顺序在未训练编码器的输出上用 k-means 初始化（10 轮，初始中心是 `randperm` 抽的不同视频）；全批量 Adam（学习率 1e-3），3,000 步；每 200 步（最后一步除外）按层的顺序，把这一刻没用到的码字换成有放回随机抽的视频的当前残差（`randint`）。
  - 检查：训练后任何一层用到的码字少于 32 个，就用同一种子、从头、步数加倍重训一次（重置照样每 200 步、最后一步除外）；仍不满足就照用，在结果里写明。
  - 只按这一份设置训练，不按推荐指标调。
- **语义 ID**：每个视频 3 位码。前三位相同的视频按 `numpy.random.default_rng(s).random(10728)` 给的随机键（并列再按视频编号）排序，依次加第 4 位区分码 0、1、2……，所以每个视频的 4 位码唯一。报告每层用到的码字数、前三位重复的视频数和最大的重复组。
- **生成模型**：只有解码器的 Transformer。每个视频是 4 个 token；前三位的码字表各 64 个，第 4 位取该种子最大区分码加 1，连同空位按偏移拼成一张 token 嵌入表。输入 = token 向量 + 位置向量 + “第几位”向量（不乘 √d），输出层和 token 嵌入共用权重。每一位只在本位的码字里做 softmax，训练和解码都一样。dropout 0.1、4 头，批大小 128 个窗口，学习率 1e-3，最多 40 个 epoch。
- **解码**：前缀树约束的束搜索，束宽 100。历史只算一次并缓存每层的 key 和 value，之后每生成一位只算新 token。树只含该用户的候选（§2.2）；某个前缀下没有候选时不再扩展。视频得分是 4 位对数概率之和（不在树的分支里重新归一化），按得分取前 100 个。

### 3.6 打乱语义 ID（对照）

- 和 §3.5 完全相同，只是把种子 s 的文本语义 ID 的 4 位码在视频之间打乱：用 `numpy.random.default_rng(s)` 先在候选池的 3,327 个视频之间、再在池外的 7,401 个视频之间各打乱一次（各自按视频编号升序排好后取 `permutation`）。码的集合、整个候选池和池外各自的前缀树形状都不变，只是不再保留视频和文本语义的对应。按用户排除候选之后，可用的码和解码树仍可能和文本版不同；两版又各自调参，最终结构可能不同。所以 H3 比较的是两条各自调好的流程，包括候选过滤和束搜索剪枝的影响，不能全部归结为文本语义的作用。

### 3.7 调参网格

调参都用种子 0，按验证子集的 Recall@100 选：

| 模型 | 网格（先列的因子变得最慢） |
| --- | --- |
| logQ 双塔 | 学习率 {1e-3, 3e-3} × 编号向量维 d_e {32, 64} |
| SASRec | 隐维 {64, 128} × dropout {0.2, 0.5} |
| 文本语义 ID、打乱语义 ID（各自调） | 隐维 {128, 256} × 层数 {2, 4} |

- 网格按各类模型常用的范围定，四个可学的模型各 4 个配置；不追求优化预算相同，结果里报告每个模型的参数量、实际 epoch 数和耗时。
- 打乱语义 ID 调参和训练都用自己的选择，不沿用文本版的配置。

### 3.8 种子

- 每个可学的模型取选定配置，种子 0、1、2 各训练一个。种子 0 就是调参时那次训练。
- 文本语义 ID 的种子 s 用种子 s 训练的 RQ-VAE 给的语义 ID；打乱语义 ID 的种子 s 打乱的是同一份。
- 种子决定参数初始化、数据顺序和 dropout；验证子集、代理和测试用户、借用的供体都和种子无关。

### 3.9 冒烟和缩小规则

- 冒烟：每类模型取网格里最大的配置训练 1 个 epoch，再对验证子集完整排一次（语义 ID 模型跑真实的束搜索），记训练耗时、排序耗时、显存峰值和训练损失，不输出验证指标。
- 按冒烟耗时推算全部调参（4 类 × 4 个配置 × 最多 epoch 数 × 每 epoch 的训练加验证）。超过 10 小时就依次缩小，直到不超过：①语义 ID 和 SASRec 的最多 epoch 数 40 → 25（直接按 25 重算）；②验证子集 2,000 → 1,000 人（`numpy.random.default_rng(1).choice(原 2,000 人, size=1000, replace=False)`，排序耗时按一半折算）；③语义 ID 网格的隐维 256 → 192（重跑隐维 192、4 层的冒烟再算）。三步用完仍超过就停下，在协议末尾追加处理办法，不再自动缩小。缩小情况写进冻结一节。

## 4. 指标

- **主指标**：Recall@100。稠密测试：前 100 个里命中的目标数 / 目标数。有偏测试：§2.2 的 Recall_w@100。
- **次要指标**：Recall@20、@50，NDCG@20、@50、@100。稠密测试用二值增益，理想值按 min(目标数, K) 个命中算；有偏测试的增益是 w_i，理想值按目标权重从大到小排的前 K 个算。
- 每个用户先对 3 个种子取平均（每个种子有自己的推荐列表），再在用户之间等权平均。

## 5. 统计与判定

### 5.1 重抽样

- 以用户为单位做 10,000 次联合 bootstrap（种子 0，复用 `receval.stats.joint_user_bootstrap`）：每次重抽的用户对所有模型、所有测试都相同。给 95% 百分位区间、标准误和双侧 p；p 为 0 时写“< 0.0002”。H1、H2 共用一个人群，H3 另定，各自重抽样；借用曝光集合和自然测试也各自重抽样。
- **种子支持**：每个对比按同一种子编号 s = 0、1、2 的推荐列表各算一次（热度只有一份列表，和对方的三个种子分别配对），数 3 个里有几个和种子均值同号。

### 5.2 主假设（一族，Holm，α = 0.05）

| | 对比 | 预期 | 理由 |
| --- | --- | --- | --- |
| H1 | D（文本语义 ID − SASRec） | > 0 | 稠密测试里冷门、低曝光视频的正样本和热门视频同权，有偏测试里它们权重小，冷门组权重为 0。SASRec 在这些视频上缺少正向交互的监督，语义 ID 可以借同前缀的相似视频生成它们。 |
| H2 | D（文本语义 ID − logQ 双塔） | ≠ 0，不预设方向 | 两者用同一份文本，一个生成码、一个做向量检索；没有足够依据判断哪种用法在稠密测试上更占便宜。 |
| H3 | Δ稠密（文本语义 ID − 打乱语义 ID） | > 0 | 打乱只去掉视频和文本语义的对应，码的集合、前缀树形状和训练方式都不变。 |

- 三个双侧 p 一起做 Holm。成立要同时满足：Holm 校正后拒绝原假设；3 个种子里至少 2 个和种子均值同号；H1、H3 的点估计方向和预期一致。H2 成立只说明“曝光计权对两个模型的影响不同”，报告方向，不说事先预测了谁占便宜。三条都允许不成立。
- H1 比较的是两套系统（文本加生成，对纯编号加打分），成立也只说明系统层面的差距变化，不能单独归因于文本或生成。H2 的两边共用输入文本，H3 的两边共用生成模型这一族（§3.6 的限定照样适用）。
- 每条报告点估计、95% 区间、p 值、Holm 结论、标准误、Holm 第一步的最小可检出差（功效 0.8，3.236 倍标准误）和种子支持。

### 5.3 次要分析（只报告）

- 10 对模型在稠密、有偏两份测试上的差和 D，都在 H1 人群上配对算，每列 10 个一起做 Holm；稠密测试上的 10 对差另在 H3 人群上报一次。
- 借用曝光集合：在它的人群上算 10 对差 Δ借用 和配对的 D = Δ稠密 − Δ借用，每列一起做 Holm；另报每人平均的 m_u，以及各模型 Recall@100 和 10 对差的蒙特卡洛标准误：每个用户先对 3 个种子平均得到各次有效抽样的值 y_{u,r}，在 m_u ≥ 2 的用户上算 s_u² / m_u（s_u² 是这几次的样本方差），合成 √(Σ s_u² / m_u) / 人群人数；m_u = 1 的用户不计入。它只反映 20 次供体分配的随机性，不能和用户 bootstrap 的标准误互换。
- 自然测试：5 个模型的 Recall@100 和 10 对差（Holm）；5 个模型在自然测试、借用、有偏、稠密四种测试上的排序两两算 Kendall τ-b（只有 5 个模型，只作描述）。
- 热度分组：稠密测试上每个模型在 5 组里的召回（每个用户先算该组命中目标数 / 该组目标数，没有该组目标的用户不算，对种子平均，再在用户间等权平均），以及每个模型前 100 个推荐落在各组的比例（H3 人群，对 3 个种子平均）。
- 次要指标上的 H1–H3 三个对比，报告点估计和 95% 区间。
- 语义 ID 诊断：每层用到的码字数、前三位重复的情况；各模型的参数量、实际 epoch 数、训练和束搜索的耗时。

### 5.4 功效检查（冻结模型组之前）

- 用代理用户、选定配置、种子 0 的模型，只算 H1–H3 三个统计量的 bootstrap 标准误，不输出它们的值。人群照 §2.2 在代理用户里定。
- 按分配人数折算到测试用户：标准误乘以 √(280 / 1,121) ≈ 0.4998，假设两边合格率和方差相近；最小可检出差 = 3.236 × 折算后的标准误。这是固定种子 0、正态近似下、只针对 Holm 检验的参考门槛，不含“至少 2 个种子同号”这一条。只报告，不据此改设计；打开测试集后用正式的三种子均值的标准误另算一次。
- 标准误必须全部有限且大于 0，否则中止。

## 10. 开封后的探索：束搜索误差和残差 k-means 码表（2026-11-03 追加）

写于看到 RESULTS 的全部结果之后，跑本节之前。只算探索：不改 H1–H3 的判定和冻结的模型组，测试集不重新打开，读的是 2026-11-01 打开时登记过的两份文件。

### 10.1 束搜索误差

- **为什么加**：§3.5 用束宽 100 的前缀树约束束搜索取前 100 个。每一位只留得分最高的 100 个前缀，前两位得分低、后两位得分高的视频可能被剪掉。RESULTS 里文本语义 ID 的 Recall@100 低于 SASRec，在借用曝光和自然日志上也低于双塔，没有区分是模型打分的问题还是搜索剪枝的问题。研究三要在全池上精确计算策略分布和 KL，也需要知道精确打分的开销。
- **精确打分**：同一个 `generative.beam_search`，束宽取候选池大小 3,327。每一位的前缀数都不超过候选数，所以不会剪掉任何前缀，结果就是该用户全部可推荐视频按 4 位对数概率之和的精确排序；取前 100 个，并列的次序同束搜索（按叶子编号稳定排序）。
- **核对**（任一条不满足就中止）：
  1. 用束宽 100、每批 128 个用户重排一遍（同正式分析），5 个模型在稠密、有偏、借用曝光、自然日志四种测试上的 Recall@100 与正式分析 `20261101-165505-analysis-c8c25f` 的差都小于 1e-12。
  2. 精确打分的算法：每个语义 ID 模型文件用 `numpy.random.default_rng(0)` 从稠密测试用户里抽 8 人，取每人的精确前 100 个，再从其余可推荐视频里抽 200 个，用 `generative.exact_scores`（逐个视频 teacher forcing 的慢版本，建在这些视频的子前缀树上）重算 4 位对数概率之和。这一步两边都关掉 TF32，最大绝对差不超过 1e-4（同 `tests/test_genrec.py` 的容差）。开着 TF32（正式分析的数值设置，`tune.device()` 打开）时两边的最大差只报告。
- **比较**：束宽 100（正式）、200、400 和精确打分，对 12 个语义 ID 模型文件（文本、打乱语义 ID 各 3 个种子，加 §8 的 6 个敏感性模型），在稠密测试的 1,121 人和自然测试的 4,872 人上各排一次。热度、双塔、SASRec 不用束搜索，沿用一次排序。
  1. **重合率**：每人束搜索前 100 与精确前 100 的交集占 100 的比例。报告均值、P10 和完全相同的人数占比，三个种子分别报告。
  2. **数值噪声底**：束宽 100 分别按每批 128 人和 16 人（精确打分用的批大小）排，报告两份前 100 的重合率。
  3. **Recall@100**：四种测试上“束宽 B 的值 − 精确的值”。人群同 RESULTS：稠密和有偏是 H1 人群 1,121 人，借用曝光 1,117 人，自然日志 4,872 人。三个种子先平均；每种人群各做一次用户 bootstrap，10,000 次，种子 0，给 95% 区间。
  4. **模型比较**：用每种搜索的前 100 重算 H1–H3（主分析和 §8 敏感性块各一套）、四种测试上 10 对模型的差和 Kendall τ-b，函数全部沿用 `genrec.analysis`。只报告，不改判定。
  5. **开销**：每个模型文件在每种搜索下的排序秒数（前后 `torch.cuda.synchronize`）、显存峰值（`torch.cuda.max_memory_allocated`）和每批用户数。
- **闸门**（为研究三事先定的）：出现下面任意一条，就算“搜索误差足以改变模型比较”，研究三从生成策略里取前 K 个时一律用精确打分：
  - 某个语义 ID 模型（主模型组或敏感性块）在某种测试上，“束宽 100 − 精确”的 Recall@100 差，95% 区间不含 0 且绝对值不小于 0.005。0.005 约等于 H3 的最小可检出差，也约等于文本语义 ID 对双塔在稠密测试上的差。
  - 某对含语义 ID 模型的差，在束宽 100 和精确打分下方向相反，且两边的 95% 区间都不含 0。
  - H1–H3 任一个在精确打分下的判定（Holm、种子支持和方向一起算）和主分析不同。

  一条都没出现时，研究三仍可按开销决定用精确打分。

### 10.2 残差 k-means 码表

- **为什么加**：§3.5 的码表来自 RQ-VAE，要训练编码器和码本。残差 k-means 直接在文本向量上逐层聚类，没有可学的编码器。§3.5 没有比较这两种码表。
- **码表**：
  - 输入是 §3.5 的同一份 Qwen3 文本向量（10,728 × 1,024，L2 归一化），不过编码器。每层在上一层的残差上聚类，3 层 × 64 个码，再用 `semantic_id.disambiguate(codes, s)` 加第 4 位区分码。种子 s = 0、1、2。
  - **普通版**：每层调用 `semantic_id._kmeans(残差, 64, 10, gen)`。`gen = torch.Generator().manual_seed(s)`，三层依次共用；初始中心是 `randperm` 抽的不同视频；空的中心保持原位。
  - **平衡版**：初始中心和普通版相同（同一个生成器、同样的抽法），每轮分配时每个中心最多收 ⌈10,728 / 64⌉ = 168 个视频：把全部（视频，中心）对按距离从小到大排（并列按视频编号、再按中心编号），依次把还没分配的视频分给还没收满的中心；更新中心同普通版，10 轮。最后一轮的分配就是这一层的码。
  - 报告每层用到的码字数、`semantic_id.collision_stats`（前三位组合数、共用前三位的视频数、最大一组）、区分码最大值，以及三层之后残差范数的均值（输入范数是 1）。
- **训练**：文本语义 ID 的选定配置（隐维 256、4 层），其余同 §3.5 和 §3.1，早停规则同主模型组（不用 §8 的至少 5 个 epoch）。两种码表各训 3 个种子，复用 `train.train_run`，只把码表换掉，登记为 purpose `posthoc-rqkmeans-plain` 或 `posthoc-rqkmeans-balanced`。码表文件存进输出目录并记 sha256。
- **比较**：
  - 主看验证子集 Recall@100，即选模型用的同一个量，和 RQ-VAE 文本语义 ID 的三个种子（0.0564、0.0529、0.0601）比。
  - 测试集上只作探索：束宽 100 和精确打分各一套，四种测试上的 Recall@100，以及对 RQ-VAE 文本语义 ID、SASRec、双塔的差。三个种子先平均，用户 bootstrap 同 10.1，逐种子另报。不做 Holm，不下结论。
- **脚本与输出**：
  - `scripts/sid_search_diagnosis.py` 写 `.runs/kuairec/posthoc/<运行编号>/sid_search.json`。
  - `scripts/rqkmeans_ablation.py` 写 `.runs/kuairec/posthoc/<运行编号>/rqkmeans.json`，码表也在这个目录。
  - 都登记在 `.runs/kuairec/registry.jsonl`，输出复制进 `evidence/kuairec/posthoc/`。表由 `scripts/make_sid_posthoc_tables.py` 生成，写进 RESULTS 的新一节。

### 10.3 TF32 开关对精确打分的影响（2026-11-03 追加，写在看到 §10.1、§10.2 结果之后、跑本节之前）

- **为什么加**：§10.1 的精确打分和正式分析一样开着 TF32。关掉 TF32 时精确打分和 teacher forcing 的差在 1e-4 以内，开着时同一个视频的对数概率之和随计算方式会差到 7.8e-3。排在第 100 名附近、得分接近的视频可能因此进出前 100。§10.1 的噪声底只换了分批大小，不能直接回答“闸门里的换号会不会只是数值精度造成的”。这是 RESULTS §9 审核时提出的。
- **做法**：
  - 模型和人群同 §10.1：12 个语义 ID 模型文件，稠密测试（1,121 人）和自然日志（4,872 人）两个人群。热度、双塔、SASRec 不经束搜索，照 §10.1 排一次。
  - 每个语义 ID 模型文件用精确打分（束宽 3,327、每批 16 人）排两遍：TF32 开（同 §10.1）和 TF32 关。分批大小相同，只差 TF32。
  - 核对：TF32 开的这一遍和 §10.1 运行 `20261103-193144-posthoc-sid-search-4f5fb8` 的精确打分结果，四种测试的 Recall@100（主模型组和敏感性块）最大差在 1e-12 以内。对不上照实报告，不中止。
- **报告**：
  1. 每个模型文件、每个人群，TF32 开和关的前 100 的人均重合率、P10、完全相同的人数占比。
  2. 四种测试上 Recall@100 的“开 − 关”，三个种子先平均，每种人群各做一次用户 bootstrap（10,000 次，种子 0）。
  3. TF32 关时的 H1–H3（主模型组、敏感性块）和 Kendall τ-b，与 TF32 开对照。
  4. §10.1 闸门里的 5 处换号，在 TF32 关的精确打分下的点估计和区间；16 处偏移按 TF32 关重算。
- **怎么用**：只报告，不改 §10.1 的判定。哪一处换号在 TF32 关时区间跨 0 或换回原号，RESULTS §9 里对应的说法就改成“依赖数值精度”。
- **脚本与输出**：`scripts/sid_tf32_check.py` 写 `.runs/kuairec/posthoc/<运行编号>/tf32_check.json`，登记在 `.runs/kuairec/registry.jsonl`，输出复制进 `evidence/kuairec/posthoc/`，表写进 RESULTS §9。
