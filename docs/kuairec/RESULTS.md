## 结论

1. **稠密测试和自然日志给出的模型排序不一致**。只有 5 个模型，以下只作描述。
   - 稠密测试：1,121 个小矩阵测试用户，候选是他们在小矩阵里有标签的视频。Recall@100 依次为热度 0.257、SASRec 0.226、文本语义 ID 0.200、双塔 0.195、打乱语义 ID 0.121。
   - 自然日志：9/01–9/05，4,872 个其他用户。依次为 SASRec 0.076、双塔 0.065、文本语义 ID 0.047、打乱语义 ID 0.042、热度 0.033。
   - 两种排序的 Kendall τ-b 是 0。10 对里方向相反的有 5 对，其中 4 对都和热度有关。
   - 在有借用目标的 1,117 个稠密测试用户上，只把目标限制在另一个用户验证窗口里实际看到的视频（借用曝光集合，20 次供体分配取平均），排序的点估计就和自然日志一样（τ-b = 1）。其中热度和打乱语义 ID 只差 0.00001，当成并列算 τ-b 是 0.95。
   - 稠密测试和自然日志方向相反的 5 对，在借用曝光上也都换了号，其中 4 对两边都显著。例如在这 1,117 人上，热度对双塔的差在稠密测试上是 +0.062，在借用曝光上是 −0.063。
2. **按曝光量加权的有偏测试没有改变排序，但放大了热度的领先**。有偏测试和稠密测试的排序相同（τ-b = 1）。热度对另外 4 个模型的领先，有偏测试上比稠密测试上大 0.074–0.087；这 4 个 D 全部显著，3 个种子都同号。
3. **主假设**（Recall@100，一族 Holm）：
   - H1（D：文本语义 ID − SASRec，预期 > 0）**未检出**。点估计 +0.0001，95% 区间 [−0.0014, 0.0017]，最小可检出差 0.0025。
   - H2（D：文本语义 ID − 双塔，不预设方向）**成立**：−0.0122 [−0.0138, −0.0105]，3 个种子里 2 个同号。文本语义 ID 对双塔的领先在稠密测试上是 0.005，在有偏测试上是 0.017，被曝光加权放大到约 3.4 倍。
   - H3（稠密测试：文本语义 ID − 打乱语义 ID，预期 > 0）按预注册规则**成立**：+0.079 [0.075, 0.083]，3 个种子都同号。但三个种子的值是 +0.005、+0.112、+0.119，大的两个来自只训了 1 个 epoch 的打乱模型（协议 §8）。另外两个模型各自调参，H3 比的是两条流程，不全是文本语义的作用（协议 §3.6）。
4. **§8 的敏感性分析**（两个语义 ID 模型至少训 5 个 epoch 再挑最好的，不进判定）：
   - H3 降到 +0.011 [0.009, 0.013]，主分析的 +0.079 里约 86% 随之消失。种子 0 上是负的（−0.026）。这 +0.011 同样是两条各自调参的流程之差。
   - H1 是 +0.0049 [0.0034, 0.0064]，H2 是 −0.0074 [−0.0089, −0.0058]。三个 p 都小于 0.0002，都是 3 个种子里 2 个同号。
5. **按主指标 Recall@100，文本语义 ID 没有赢过 SASRec**。这是正式分析的束宽 100；开封后探索精确打分时（§9，不改正式结论），稠密测试上两者点估计接近、未检出差异，有偏测试上文本语义 ID 更高，借用曝光和自然日志上仍是 SASRec 更高。
   - 三种子均值在四种测试上都低于 SASRec：稠密 −0.026，有偏 −0.027，借用曝光 −0.041，自然日志 −0.030。稠密和有偏测试上只有种子 0 例外（+0.004、+0.029）；借用曝光和自然日志上 3 个种子都低于 SASRec。
   - 但在稠密测试的头部，它反而更高：Recall@20 高 0.004，NDCG@20 高 0.034，NDCG@50 高 0.023（都 Holm 显著，3 个种子里 2 个同号）；Recall@50 的差不显著。所以只能说前 100 的召回不如 SASRec，不能说全面更差。
   - 对双塔，稠密测试上高 0.005（2 个种子同号），自然日志上低 0.018（3 个种子同号）。
   - 冷门组是训练窗口里没有其他用户行的 555 个视频，它们的目标所有模型都几乎召不回，文本语义 ID 只有 0.0007。低曝光组里文本语义 ID 是 0.126，也低于 SASRec 的 0.183 和双塔的 0.168。H1 的理由是“语义 ID 能借同前缀的相似视频把冷门视频生成出来”，数据里没有观察到能支持这一条的冷门、低曝光召回优势。
6. **种子之间的差比用户 bootstrap 的区间大得多**。H1 三个种子的值是 −0.025、+0.020、+0.006，而区间半宽只有 0.0015。区间只反映固定模型下的用户抽样，不含训练的随机性。种子之间的波动远大于区间半宽时，只看区间不够，还要看逐种子的结果是否一致。

## 1. 设定（细节见协议）

- **数据**：KuaiRec 2.0。小矩阵是 1,411 个用户 × 3,327 个视频，几乎全观测；大矩阵的数据在 7/05–9/05 之间，中间有缺口（`docs/kuairec/DATA.md`）。候选池就是小矩阵的 3,327 个视频。
- **数据的限定**（协议 §1.2）：
  - 小矩阵不是纯随机曝光：快手先挑出彼此看过很多的用户和视频，再把没看过的对在 15 天里插进推荐流补齐。它回答的是“几乎每一对都有标签时”排得准不准，不是“随机推荐时”的反应。
  - 小矩阵和大矩阵是同一段时间采的，稠密测试是同期矩阵的补全，不是预测未来。
  - 视频文本 2024-06 发布，采集时点不明，可能晚于日志。
  - 有偏测试只模拟非个性化的热度删失，不模拟旧策略按个人兴趣挑视频的偏差。
- **切分**：
  - 训练 7/05–8/10，用大矩阵全部用户；验证 8/27–8/31，用其他用户。
  - 自然测试 9/01–9/05，用其他用户；稠密测试是小矩阵里测试用户的行。这两份在打开前没有进过任何缓存和模型。数据审计时读过大矩阵这几天的行，只用来数重复行（协议 §9 第 6 条）。
  - 正样本是 watch_ratio > 2。
- **用户**：有训练正样本的 1,401 个小矩阵用户，按 2:8 分成代理 280 人、测试 1,121 人。
- **曝光量和有偏测试**：
  - 曝光量 w_i 是训练窗口里其他用户在视频 i 上的行数。w = 0 的 555 个视频是冷门组，其余按 w 等分成 4 组，每组 693 个。
  - 有偏测试用同一份候选和目标，只是每个目标按 w_i 计权，算 Recall_w@100。
- **模型**（5 个；可学的 4 个各训 3 个种子，只在验证子集上调参）：
  - 热度。
  - 双塔：输入是编号、类别和冻结的 Qwen3 文本向量，用 logQ 校正批内负采样。
  - SASRec：全量 softmax。
  - 文本语义 ID：Qwen3-Embedding-0.6B 文本向量，经 RQ-VAE 得到 3 层 × 64 个码再加 1 位区分码，用 decoder-only Transformer 生成，前缀树约束束搜索，束宽 100。
  - 打乱语义 ID：同一套码，在候选池内、池外分别打乱。
- **统计**：
  - 每个用户先对 3 个种子取平均，再做 10,000 次联合用户 bootstrap。
  - D = Δ稠密 − Δ有偏。H1–H3 一族做 Holm。
  - 成立还要满足两条：3 个种子里至少 2 个同号；H1、H3 的方向和预期一致。

## 2. 人群

- **稠密测试和 H1–H3**：1,121 人全部有目标，目标权重也都大于 0，没有排除。每人目标数的 P10、P50、P90 是 26、97、376。
- **借用曝光**：
  - 1,117 人。另外 4 人 20 次抽样都没有目标，被排除。

## 5. §8 的敏感性分析（不进判定）

两个语义 ID 模型用选定配置、种子 0–2 重训：前 5 个 epoch 不早停，最好的 epoch 只在第 5 个 epoch 起挑，其余同主模型组。

- 训练是确定性的。文本种子 1、2 和打乱种子 0 的最好 epoch 本来就在第 5 个 epoch 起，重训得到的就是同一个模型。
- 变了的是另外三个（epoch 编号从 0 起）：文本种子 0 的最好 epoch 从 2 变成 6，验证值从 0.0564 降到 0.0511；打乱种子 1、2 从 0 变成 15 和 9，验证值从 0.0621、0.0476 变成 0.0579、0.0559。

## 7. 能说什么、不能说什么

- **能说**：
  - 在 KuaiRec 的这 5 个模型上，近乎全观测的稠密测试和自然日志测试给出的排序不一致（τ-b = 0）。
  - 在有借用目标的 1,117 个稠密测试用户上，把目标限制在别人实际看到过的视频里、按 20 次供体分配平均，排序的点估计和自然日志相同。
  - 按曝光量计权会放大热度的领先，也会改变文本语义 ID 和双塔的差距（H2）。
- **借用曝光和自然日志为什么一致，可能的一个原因**：两者用的都是 8 月底以后的曝光，而热度按 7/05–8/10 的正样本排序。这一条没有单独检验。
- **不能说**：
  - 不能说“稠密测试不可靠”或“自然日志更对”。两者回答的问题不同：一个是全部有标签的视频里召回多少，一个是实际曝光过的视频里召回多少。
  - 自然日志用的是另一批用户、另一套候选，τ-b = 0 不能只归因于曝光方式。
  - 不能说生成式召回比 SASRec 好：按 Recall@100，四种测试上都是 SASRec 更高（正式分析的束宽 100；开封后探索的精确打分下，稠密测试上未检出差异、有偏测试上文本语义 ID 更高，借用曝光和自然日志上仍是 SASRec 更高，见 §9）。也不能说它全面更差：稠密测试的前 20、前 50 位，文本语义 ID 更高。
  - 不能把 H3 的 +0.079 当成文本语义带来的增益。敏感性分析里只剩 +0.011，自然日志上是 +0.005；两者也都是两条各自调参的流程之差。
  - H1 未检出，不等于两种测试对这两个模型的影响一样大。区间落在 ±0.002 以内，次要指标上 H1 还有方向相反、区间不含 0 的值。
  - 有偏测试是按曝光量模拟的，不是真实日志；小矩阵也不是随机推荐的反应（§1 的数据限定）。
  - 双塔的 logQ 校正的是批内负采样，不是曝光去偏。
  - 结论只限于离线评测，没有线上效果。

## 9. 开封后的探索：束搜索误差和残差 k-means 码表（协议 §10，只报告）

- **为什么做**：§3.5 用束宽 100 的前缀树约束束搜索取前 100 个，每一位只留得分最高的 100 个前缀，前几位得分低、后几位得分高的视频可能被剪掉。正式分析里文本语义 ID 的 Recall@100 低于 SASRec，没有区分是模型打分的问题还是搜索剪枝的问题。另外 §3.5 的码表来自 RQ-VAE，没有和直接在文本向量上逐层聚类的残差 k-means 码表比过。
- **怎么做**：
  - **束搜索误差**（协议 §10.1）：精确打分就是束宽取候选池大小 3,327 的同一个 `beam_search`，什么都不剪。12 个语义 ID 模型文件（文本、打乱语义 ID 各 3 个种子，加 §8 敏感性的 6 个）各用束宽 100、200、400 和精确打分排一遍，人群同正式分析。运行 `20261103-193144-posthoc-sid-search-4f5fb8`。
  - 两项核对都过了：束宽 100 按每批 128 人重排，四种测试的 Recall@100 和正式分析的最大差是 0（容差 1e-12）；精确打分和逐个视频 teacher forcing 的打分（每个模型文件 8 个稠密测试用户，每人 300 个视频）比，关掉 TF32 时最大差 2.9e-6–1.7e-5（容差 1e-4）。排序时和训练一样允许 TF32，两种计算方式的矩阵形状、内核和累加方式不同，观测到的对数概率之和最大差 7.5e-4–7.8e-3，只报告；噪声底（束宽 100 按每批 128 人和 16 人各排一次）间接反映这种浮点抖动。
  - **残差 k-means 码表**（协议 §10.2）：在同一份 Qwen3 文本向量上逐层聚类，3 层 × 64 个码，再加区分码。普通版直接用 k-means；平衡版每个中心最多收 168 个视频。用文本语义 ID 的选定配置各训 3 个种子，早停规则同主模型组。运行 `20261103-195312-posthoc-rqkmeans-6d05fb`，6 个训练运行见表 9.J；重载后验证值和登记值的差是 0，表里 RQ-VAE 的测试值和上一个运行的差也是 0。
  - **TF32 开关**（协议 §10.3，审核后追加，写在跑之前并先提交 8945c53）：12 个语义 ID 模型文件用精确打分各排两遍，每批 16 人，只差 TF32 开关，再按 TF32 关的结果重算闸门。运行 `20261103-212131-posthoc-sid-tf32-73469c`，TF32 开的那遍和上面的诊断运行差 0。

     - 束宽 100 下，两种残差 k-means 在稠密、有偏、借用曝光上都低于 RQ-VAE（−0.005 到 −0.025），自然日志上高 0.0045–0.0062。
     - 精确打分下，普通版和 RQ-VAE 在稠密、有偏、借用曝光上的差都在 ±0.001 以内，区间含 0；平衡版稠密低 0.007、有偏低 0.012，借用曝光上未检出差异。自然日志上两种都比 RQ-VAE 高 0.005–0.006，区间不含 0。
     - 小矩阵的三种测试上，束宽 100 对残差 k-means 压得比 RQ-VAE 更多：稠密测试上普通版少了 0.043，平衡版 0.038，RQ-VAE 0.026。固定这些已训练的模型、只把测试时的解码换成精确打分，这三种测试上 RQ-VAE 对普通版的领先点估计就缩到 −0.0010 到 +0.0005（RQ-VAE 减普通版），对平衡版的领先缩小约一半到全部。这些比例没算区间，也不能读成一般意义上剪枝造成的份额。自然日志上不是这样：束宽 100 下两种残差 k-means 本来就高于 RQ-VAE，普通版被压低的也比 RQ-VAE 少。
     - 普通版被压得多，可能和它前三位共用得多有关（候选池里 1,548–1,886 个视频和别的视频共用前三位，RQ-VAE 是 381–394 个）：同一前缀下视频多，前缀的得分和单个视频的得分差得更远。这一点没有单独检验。
     - 借用曝光和自然日志上，三种码表都仍低于 SASRec 和双塔。
- **能说**：
  - 在 3,327 个视频的池子上，束宽 100 的约束束搜索会漏掉精确前 100 里的一大块（主模型组文本语义 ID 漏掉 36%–47%），系统性地压低语义 ID 模型的 Recall@100，压低多少随模型和码表变；束宽 400 已和精确打分几乎一样。
  - 精确打分下，文本语义 ID 在稠密测试上和 SASRec 未检出差异、在有偏测试上更高，但在借用曝光和自然日志上仍低于 SASRec 和双塔。预注册 H1–H3 的判定和“稠密测试与自然日志排序不一致、借用曝光与自然日志的排序点估计一致”都不变。
  - 码表之间的比较也受搜索误差影响。精确打分下，普通残差 k-means 和 RQ-VAE 在小矩阵的三种测试上没有检出差别；验证子集上（选模型用的束宽 100）两种残差 k-means 和 RQ-VAE 也都没有检出差别。
- **不能说**：
  - 这是开封后的探索，不改正式分析的数和判定。结论 5、§7 里“四种测试上都是 SASRec 更高”说的是正式分析的束宽 100。
  - 精确打分只在 3,327 个视频的池子上验证过正确性和开销，没验证更大的池子或线上延迟；不能推到大候选池的线上系统，能说的只是束宽要和池子、码表一起调。
  - 残差 k-means 没调层数、码本大小和迭代次数，生成模型也没为新码表重新调参；测试集上的比较没做 Holm，不下结论。平衡版只是每个中心设容量上限的一种贪心实现。
  - TF32 的影响只在这 12 个模型文件、这两个人群上直接核对过（结果 7）；残差 k-means 的 6 个模型没做这项核对。
