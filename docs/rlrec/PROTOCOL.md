## 1. 研究问题与假设

**问题**：从同一个 SFT 起点出发、在相同的平均 KL 偏离下，拿常规日志上训的点击率模型当奖励去优化生成式推荐策略，策略在随机曝光上的价值会不会上升？用少量随机曝光数据纠正奖励（校准，或训练时混入随机数据），收益会不会更大？

- **两种优化方式都进主假设族**：
  - **O3 解析最优** π_β ∝ π0·exp(r/β)，是“奖励期望减 β 倍 KL”这个目标的精确最优解。候选池只有 7,583 个视频，可以在全池上精确算，比较奖励时不混进优化器的噪声，回答“奖励本身好不好”。它不训练生成模型，是诊断。出处见 `LITERATURE.md` §3（DPO 原论文）、§4（RGD）。
  - **O4 RLOO** 是实际的策略梯度后训练，更新生成模型的参数，回答“训练出来的生成模型上还成不成立”。O4 优化同一个目标（§6.2，KL 系数 λ 对应 β）。
  - O3 不是 V₅₀₀ 的上界：它最优化的是奖励期望减 KL，V₅₀₀ 评的是“前 500 个里均匀推一个”，RL 超过它不矛盾。O3 还直接用到奖励模型的全部输入（用户编号、画像、统计量），生成模型只看历史的码，所以 O3 − O4 的差同时含优化器、模型容量和输入信息的差别，不是单纯的优化器差距。
- **主指标**：K = 500 的列表价值 V₅₀₀（§7），名义倾向。K = 500 是可行性审计闸门的结论（`FEASIBILITY.md` §6）。
- **主 KL 档**：1 nat。“相同 KL”指 KL 子集上的平均 KL 相同（§6.1）；测试人群上的 KL 均值、分位数和列表重合照报，不保证每个用户的 KL 一样。
- **五个主假设**（一族 Holm）：
  - **H1（迁移，解析最优）**：V₅₀₀(π_β^R1) − V₅₀₀(π0)，不预设方向，双侧。
  - **H2（校准，解析最优）**：V₅₀₀(π_β^R3) − V₅₀₀(π_β^R1) > 0。R3 是 R1 加按热度分组的 Platt，里面含全局部分；全局和分组各自的作用由次要指标 R2 − R1、R3 − R2 拆开。
  - **H3（随机数据，解析最优）**：V₅₀₀(π_β^R5) − V₅₀₀(π_β^R4) > 0。同样新、同样多的数据，只差曝光方式（研究一 §18 的设计）。
  - **H4（迁移，RLOO）**：V₅₀₀(π_RL^R1) − V₅₀₀(π0)，双侧。
  - **H5（校准，RLOO）**：V₅₀₀(π_RL^R3) − V₅₀₀(π_RL^R1) > 0。
- RL 只拿 R3 对 R1 进主假设：R3 只给 R1 加校准、不重训奖励模型，两者共用同一个 LightGBM，RL 下的对比最干净；R4、R5 的 RL 只作次要（§6.2）。
- **判定**：Holm 后显著、方向符合，且 3 个 SFT 种子里至少 2 个同号，才算成立。H1、H4 显著时只报方向，显著为负只能叫“负迁移”，不能叫收益。未检出不说成“没有差别”。
- **种子的值**：SFT 种子 s 上，一个策略的值是 V_s = Σ_{u,t} 点击数_{u,s,t} / Σ_{u,t} 行数_{u,s,t}，t 取该种子下这个策略的全部模型（π0、O3 只有一个，O4 是 3 个 RL 种子），即先合并计数、再算比值，不平均各模型的比值。H1、H4 拿它和同一个 SFT 种子的 π0 比，H2、H3、H5 比同一个 SFT 种子下的两个奖励。
- **不可检验**：出现下面任何一种，这个主假设记“不可检验”、不成立，结果只描述，在 Holm 里按 p = 1 占位（族的大小不变）：用到的奖励在 1 nat 档不可达（§6.1）；O4 用到的 RL 运行有缺（§6.2 的 λ 规则下没跑）；O4 用到的任何一个主档检查点没对齐（§6.2）。混合策略缺了模型，不拿剩下的模型凑。

## 4. SFT 策略 π0

- **模型**：`genrec.generative.Generator` 的结构（只有解码器，每一位在本位码字里 softmax），历史 50 个事件。
- **训练样本**：每个合格用户训练窗口里的正样本（全部 tab）按时间排成序列（同一时间按去重后的行序），按研究二的规则切成最多 51 个事件的窗口（从末尾往前切，相邻窗口重叠一个事件，`genrec.data.windows`），损失用研究二的 `genrec.generative.loss_fn`：窗口里除第一个事件外，每个事件的 4 位码都从它之前的全部 token 预测，逐位交叉熵，不按候选掩码。所以每个用户的第一个正样本只当输入、不当目标，只有一个正样本的用户不贡献损失，不会出现空历史的目标。目标是“下一个正样本”，不限 tab 1；评价和奖励只看 tab 1。
- **策略的分布**：π(i|u) = Π_{l=1..4} p_l(c_l(i) | 前缀)，p_l 是第 l 位在“该前缀下、该用户候选里还有视频的子节点”上重新归一化的 softmax。这样 π 是用户候选上的真分布，和研究二“全层码字 softmax、事后排除候选”的打分不同，在 `src/rlrec/` 另行实现。按它逐位采样得到的对数概率，和 O4 训练时带同样掩码的 teacher forcing 算出的一致（§10 的测试）。SFT 的训练损失仍是不掩码的。前 K 个按 log π 排，并列按视频编号。全部精确计算，不用束搜索（研究二 §9）。只剩一个候选子节点的前缀，该位的条件概率恒为 1，可以不算（§10 测试兜底）。
- **选配置**：隐维 {128, 256} × 层数 {2, 4}，4 个头，学习率 1e-3（AdamW，不加权重衰减，前 200 步线性预热，梯度裁剪 1.0）、dropout 0.1、batch 128、最多 40 个 epoch。早停看常规验证集的 Recall@100（π0 的精确前 100，目标是 4/22–4/28 常规日志里 tab 1、在候选内的正样本），只在固定的 2,000 个验证用户上算（合格且有目标的用户里 `numpy.random.default_rng(1)` 不放回抽取，同研究二 §3.1）；耐心 3，前 5 个 epoch 不早停、最好的 epoch 从第 5 个起挑（研究二 §8 的教训）。种子 0 选配置（并列取网格里靠前的），再训种子 1、2。
- 只用常规验证集选 SFT，不看随机数据：研究的是“同一个起点上换奖励”，起点本身怎么来不进比较。

## 5. 奖励

r(u, i) 是预测的点击概率，取值 (0, 1)。

| 奖励 | 内容 |
| --- | --- |
| R1 | 研究一冻结模型组的 LightGBM A（3 个种子的预测取平均） |
| R2 | R1 加全局 Platt（`calibrate.fit_platt`） |
| R3 | R1 加按热度分组的 Platt（`calibrate.fit_grouped`，5 组；`calibrate.popularity_groups` 按训练期去重后全部 tab 的曝光数分组，同研究一 §8.2） |
| R4 | 研究一 §18 的 B 常规（固定轮数），3 个种子取平均 |
| R5 | 研究一 §18 的 B 随机（固定轮数），3 个种子取平均 |
| R6（次要） | 研究一 §18 的 C（只用随机 FIT 段，固定轮数），3 个种子取平均 |

- **R4–R6 重训**：§18 当时没存模型文件。照 `scripts/random_mix_fixed_rounds.py` 的设置重训（同样的抽样种子、行、轮数和 LightGBM 参数），模型文件先存档并记 sha256，再核对。核对分两步：A 的重训和冻结的 A 预测逐位相等（不看标签）；B 常规、B 随机、C 在两份测试集上按 §18 的算法（每个种子分别算 UAUC、LogLoss，再平均）重算，和 §18 的输出 `random_mix_fixed.json` 逐位相等（差 ≤ 1e-12）。这是模型组冻结前唯一读测试集的步骤，只输出“相等 / 不等”和最大差，不输出新的数。对不上就停下报告，不按测试表现重选或重训。
- **校准的数据**：R2、R3 用的随机行，就是 R5 混进训练的那 61,434 行（§18 从 FIT 段 tab 1 的 161,574 行里按 `random_mix_ablation.SAMPLE_SEED` 抽的同一批）。这样“同样一批随机数据，拿来校准还是拿来混训”数据量相同。拟合的输入是 R1 在这些行的（用户，视频）上、按下面同一个参考语境算的预测，和奖励表的算法一致。
- **校准的敏感性**（次要，只在 O3 下报）：R3 改用 FIT 段全部 161,574 行拟合；R3 仍用同样那 61,434 行，只把输入换成这些行实际语境（日期、时段）下的 R1 预测。
- 校准斜率可能被下界卡在 0（`calibrate.fit_platt` 允许）。全局斜率为 0 时 R2 对每个用户是常数、任何 KL 档都不可达，照报（§6.1）。
- **奖励表**：对全部合格用户（不超过训练期的 26,210 人）× 7,583 个视频算一张表，HOLD、测试和 O4 的训练用户都查这张表。特征按固定参考语境构造：tab 1，日期 2022-04-22（星期五），时段取去重后常规训练窗口 tab 1 行里最常见的整点（并列取小的）。LightGBM 的输入里没有用户和视频的交叉特征，只有用户列、视频列和语境列，所以分别对用户表、视频表构造编码后的列，再按用户分块广播拼成输入矩阵（§10 测试：小样本上和直接调 `receval.features.build` 逐位相等）。R1、R4、R5、R6 各存一张 float32 表并记 sha256，R2、R3 由 R1 的表和校准参数算。
- 参考语境是一个简化：同一用户的不同视频共用同一语境，奖励的差别只来自用户和视频。校准的拟合目标是“参考语境下的分数”对应的、FIT 行那种日期和时段混合下的点击概率；有限样本、Platt 的形状限制和分组收缩都不保证留出数据上校准，更不保证策略偏好的区域校准；V₅₀₀ 上升不能反过来证明奖励校准正确。

## 6. 优化方式

| 编号 | 方式 | 地位 |
| --- | --- | --- |
| O1 | SFT 策略 π0 | 起点 |
| O2 | 重排：π0 的前 2,000 个里按 r 取前 K 个 | 次要，没有 KL |
| O2′ | 纯奖励排序：在候选里直接按 r 取前 K 个（β → 0 的极限），并列按视频编号 | 次要，没有 KL |
| O3 | 解析最优 π_β(i\|u) ∝ π0(i\|u)·exp(r(u,i)/β)，在用户候选上精确归一化 | 主（H1–H3） |
| O4 | RLOO（§6.2） | 主（H4、H5） |

### 6.1 KL 和 O3

- **KL 的定义**：每个用户在候选上精确计算 KL(π‖π0)，取 HOLD 人群里固定 2,000 人的均值（`numpy.random.default_rng(2)` 从排好序的 HOLD 用户里不放回抽取，下称 KL 子集）。KL 档 0.5、1、2 nat，主档 1 nat。O3 和 O4 用同一个 KL 子集定档。
- 每个（奖励，SFT 种子，档）在 log₁₀ β ∈ [−6, 2] 上二分找 β，使 KL 子集的均值落在档位的 ±0.1% 内。找不到时记“不可达”，照报，不改档位；同时登记 β → 0 时 KL 的理论上限、区间两端的 KL 和原因（理论上限不够，还是在这个区间里数值上够不着）。
- 健全性检查（合成数据上的测试）：β → ∞ 时 π_β 退回 π0；β → 0 时退到每个用户 r 最大的候选。

### 6.2 O4：RLOO

- **运行**：
  - 主：R1、R3 两种奖励，每种 3 个 SFT 种子 × 3 个 RL 种子，共 18 次；
  - 次要：R4、R5 各 3 个 SFT 种子 × RL 种子 0（6 次）；优势除以组内标准差的 GRPO 式变体，R1、R3 各 3 个 SFT 种子 × RL 种子 0（6 次）。
- **采样**：每步从合格用户里抽 256 人（每轮打乱一次、不放回），每人从当前策略按 §4 的分布独立采 8 个视频（可以重复）；奖励查 §5 的奖励表。策略在采样和算梯度时都处于 eval 状态（不开 dropout），两次算出的对数概率一致（§10 测试）；参考模型 π0 冻结，不回传梯度。
- **梯度**：把 KL 并进奖励，r′_j = r_j − λ·[log π_θ(i_j|u) − log π0(i_j|u)]（方括号里不回传梯度）；优势 A_j = r′_j − 同组其余 7 个 r′ 的均值，不除组内标准差（GRPO 式变体才除）；损失 −mean_j(A_j · log π_θ(i_j|u))。它的期望梯度就是 E_π[r] − λ·KL(π‖π0) 的梯度（§10 测试），这个目标的最优解正是 β = λ 的 π_β。不用对 k3 估计量直接求导的写法：那样的期望梯度对应的是反向 KL。
- **λ**：取同一奖励、同一 SFT 种子在 2 nat 档的 β。在不受模型结构限制的分布里，这个目标的最优解就是 O3 的 2 nat 档，所以它是 RL 的标称终点；参数化的生成模型不保证到得了，也不保证单调地经过 0.5、1 nat。2 nat 档不可达时取 1 nat 档的 β；1 nat 档也不可达时，这个（奖励，SFT 种子）不跑 RL，用到它的主假设记“不可检验”。λ 只按这条规则定，不再调。
- **学习率**：先做一次只看 KL 的试跑（R1、SFT 种子 0、RL 种子 0），学习率 {1e-4, 3e-4, 1e-3} 各跑一次，取 1,500 步内 KL 子集均值越过 1 nat 的最小学习率；都不过就取 1e-3。R1 在 SFT 种子 0 上没有可用的 λ 时，按 R1 的种子 1、2，再 R3 的种子 0、1、2 的顺序取第一个有 λ 的组合试跑；都没有就不试跑，学习率取 1e-3，照实登记。试跑不进结果，网格和规则不再改。优化器 AdamW（不加权重衰减），不预热，梯度裁剪 1.0。
- **检查点**：最多 3,000 步。每 100 步在 KL 子集上精确算一次 KL；某次达到下一个未到档位的 85% 后，改成每 10 步算一次，并一直保持，直到越过该档（中途 KL 回落也不退出），再回到每 100 步。每个档取第一个 KL 不低于档位的检查点。它的 KL 在档位的 [1, 1.05] 倍内算“对齐”；超过 1.05 倍，或到最后都没越过（这时取 KL 最大的检查点）都算“没对齐”：检查点照存、不重选，非主档照报并写明，主档按 §1 让用到它的主假设不可检验。KL 越过 2 nat 就停。
- 训练用户和 HOLD、测试用户重叠：推荐系统的常规设定（训练期见过的用户）。RL 只用 4/21 以前的历史和奖励表，不直接读 4/21 以后的任何标签；但奖励本身间接用过 4/22–4/25 的标签（R2、R3 的校准，R4–R6 的训练）。

## 7. 评价

- **列表价值 V_K**（主指标 K = 500）：每个用户的列表 L_u 是策略的前 K 个（π0、π_RL 按自身的 log π 排，π_β 按 log π0 + r/β 排，并列按视频编号）。V_K = Σ_u 点击数_u / Σ_u 行数_u，行数_u 是该用户落在 L_u 里的随机测试行（tab 1、视频在其候选内），点击数是其中 `is_click` 之和。
- **倾向**：随机曝光从全池 7,583 个视频里均匀抽，名义倾向取 q = 1/7,583（`FEASIBILITY.md` §1）；用户看过的视频策略不会推（π = 0），那些行的权重本来就是 0。“前 K 个里均匀推一个”的权重因此是常数 7,583/K，SNIPS 就是上面的计数比，跨用户按行合并。
- **种子**：π0 和 O3 的每人行数、点击数先对 3 个 SFT 种子取平均，O4 先对全部 9 个（SFT 种子，RL 种子）取平均，再跨用户合并（同研究一 §20）。所以主估计是“等概率随机选一个种子的模型”这个混合策略的价值，不是各种子比值的平均。种子支持按 SFT 种子算，每个种子的值是它自己的计数比；逐种子的值另报。
- **次要指标**（只报点估计和区间）：
  - V₁₀₀、V₂₀₀、V₁,₀₀₀；
  - 策略本身按概率抽样的价值（权重 w = 7,583·π(i|u)，同一个全池倾向；混合策略的 π 是各模型 π 的平均）、它的有效样本量 (Σw)²/Σw²（用混合策略逐行的权重算），以及每个用户的有效支撑 1/Σπ²（报人群中位数）。只描述，不下结论；
  - HOLD 上的同一组值，和 R1、R2、R3 在 HOLD 行上的校准诊断（LogLoss、预测均值对点击率），都在模型组冻结后才算，只描述；
  - 测试人群上每个策略的 KL：均值、P10/P50/P90、按每人随机测试行数加权的均值；主假设两两比较的策略之间，前 500 的人均重合率；
  - 代理指标：R1、R3 下的期望奖励 E_π[r]；常规测试的 Recall@500（有偏）；
  - 前 500 里训练期曝光最热一组（5 等分）的占比；全部用户前 500 的并集覆盖多少视频（每个模型各算一次再平均）；`long_view` 的列表价值；每个模型（含每个 RL 种子）自己的 V_K；
  - 机制拆分：O3 下的 R2 − R1、R3 − R2、R4 − R1、R6 − R1；§5 的两个校准敏感性；O2、O2′ 下各奖励的值；
  - O4 对 O3：同奖励、同档的 V(O4) − V(O3) 和 V(O4) − V(π0)。追上比例 (V(O4) − V(π0)) / (V(O3) − V(π0)) 只在 V(O3) − V(π0) 的区间整个大于 0 时报点估计，否则不报；
  - O4 次要运行（R4、R5、GRPO 式变体）的值。
- **图**：各奖励的价值–KL 曲线（O3 全部档和 O2′；O4 主运行的 1 nat 和 RL 种子 0 的全部档）；代理奖励上升对随机曝光价值的曲线；热度占比随 KL 的变化。

## 8. 统计

- 联合用户 bootstrap 10,000 次（种子 0，`receval.stats.joint_user_bootstrap`），所有策略的每人计数一起重抽，比值在每次重抽里算。
- 五个主假设报点估计、95% 区间、双侧 p，一族 Holm；另报逐种子的值和最小可检出差（Holm 第一步、功效 0.8，5 个假设时乘数 3.4175）。这个乘数只对应固定模型、正态近似和 Holm 第一步，不含种子同号的门槛。H2、H3、H5 用双侧 p 再要求方向为正，是保守的判法。
- 次要指标只报点估计和区间，不做 Holm、不下判定。
- bootstrap 只反映用户抽样，不含训练随机性；种子之间的差另看逐种子值（研究二 §6 的教训）。3 个种子里 2 个同号只是最低要求，不是训练稳定性的置信保证。

## 9. 模型组冻结前的精度复核

- **时点**：O3 的 β 和 O4 的主运行都做完之后、模型组冻结之前。
- **状态**：先按 §1 给每个主假设登记“可检验 / 不可检验”。不可检验的留在族里按 p = 1 占位，不参加下面的精度判断，也不被精度分支删掉。
- **算什么**：对每个可检验的主假设，在 HOLD 全体上算它的差在 K = 500、1,000 下的用户 bootstrap 标准误，粗略外推到测试集，取两种外推里大的那个：按行乘 √(HOLD 行数 / (892,896 × HOLD 行的保留比例))，保留比例是 HOLD 上去掉不合格用户和训练期看过的行之后剩下的比例；按用户乘 √(HOLD 人数 / 25,437)，25,437 是合格用户数，测试人群不会更多。最小可检出差 = 3.4175 × 外推标准误。门槛是 HOLD 上 V_K(π0) 的 5%。标准误不是有限正数（退化）的，算这一档精度不通过。这是粗外推，不是正式的功效保证。
- **只输出**：HOLD 上的 V_K(π0)、各差的标准误、外推标准误、最小可检出差、每个假设的状态和分支决定。不输出差的点估计；HOLD 上的点估计等模型组冻结后作次要指标报。
- **分支**（事先定，不再加分支）：
  0. 没有可检验的主假设：记“无可检验的主结论”，全部结果只作描述。
  1. 可检验的在 K = 500 下都低于门槛：照本协议。
  2. 否则看 K = 1,000（门槛改成 HOLD 上 V₁,₀₀₀(π0) 的 5%），可检验的都过：主指标改成 V₁,₀₀₀。
  3. 还不过但至少一个过：主指标用 V₁,₀₀₀，把在 K = 1,000 下不过的可检验假设移出主假设族改作次要；族里剩下过了的和不可检验的占位，Holm 和乘数按剩下的个数算（个数变少，乘数只会变小，过了的不用再复核）。
  4. 可检验的在 K = 1,000 下都不过：记“精度不足，不承担主结论”，全部结果只作描述。
- 复核结果和决定追加进本协议，再提交模型组冻结点。

## 11. 能说什么、不能说什么（事先定）

- 能说：在 KuaiRand-Pure 的 7,583 个视频上、同一个 SFT 起点和相同的平均 KL 下，几种奖励的解析最优策略和 RLOO 训练出的策略，在随机曝光上的列表价值差多少；RL 和解析解差多少。
- 不能说：
  - “首次”。近邻工作见 `LITERATURE.md` §4、§5（HRPO、EWM、RGD 等）。
  - 线上效果；大候选池上的结论（精确计算只在这个小池子上验证过）。
  - 测试集是新的盲测（§0）；也不能说奖励模型自身的排序改进是这里的新发现（研究一已有）。
  - 名义倾向下的价值等于真实价值：随机池近似均匀，但有低频尾巴，随机视频周围仍是旧策略推的内容。
  - 奖励表用的是固定参考语境（§5），不是每次推荐时的真实语境；V₅₀₀ 上升不证明奖励在策略偏好的区域校准正确。
  - O3 是在全池上对 π0 精确重新加权，不是训练出来的生成模型；“生成式推荐的 RL 后训练”的说法只对 O4 成立。O3 − O4 的差不是单纯的优化器差距（§1）。
  - 这是冻结语境下的单步推荐优化，不是和用户长期交互的强化学习。
  - `is_click` 在 tab 1 近似“有效播放”，不直接等于通常说的点击率。
  - 奖励模型只有 LightGBM 一种结构；用户都是训练期见过的用户；不证明生成式方法本身比别的召回方式好。
  - 标题和类目是 2026 年发布的回溯表示，不是 2022 年当时就能用的信息。

### 12.1 修订一：RLOO 上的随机数据比较进主假设族（2026-11-04）

- **时点**：协议冻结之后、任何策略价值算出来之前。写这条时跑完的只有文本、语义 ID 和 R4–R6 重训核对，SFT 在跑（`.runs/rlrec/registry.jsonl`）；奖励表、β、RL、§9 的精度复核和 HOLD、测试上的策略评价都没开始。§5 的核对只输出相等或不等，所以作者没看过任何策略在 HOLD 或测试上的值，也没看过这些奖励优化出来的策略之间的差。
- **原因**：§1 只让 R3 对 R1 进 RL 主假设，是因为这对比较最干净，也省算力。可是混入随机数据（研究一 §18 的 B 随机）是这个项目最直接的纠偏手段，只在解析最优上判、RL 下只描述，就回答不了“这样的奖励拿去做 RL 有没有用”。多跑的代价只是本机算力。
- **H6（随机数据，RLOO）**：V₅₀₀(π_RL^R5) − V₅₀₀(π_RL^R4) > 0，判法同 H5。
- **主假设族**：H1–H6 共 6 个，一族 Holm。Holm 第一步的门槛从 0.05/5 变成 0.05/6，§8、§9 的最小可检出差乘数从 3.4175 变成 3.4799（放大约 1.8%）。§1 的种子值和不可检验规则、§9 的状态和分支都照样用在 H6 上。H6 用到 18 次 RL 运行，任何一次缺失或主档没对齐，H6 就不可检验。
- **运行**：§6.2 的运行改成：
  - 主：R1、R3、R4、R5 四种奖励，每种 3 个 SFT 种子 × 3 个 RL 种子，共 36 次；
  - 次要：优势除以组内标准差的 GRPO 式变体，R1、R3 各 3 个 SFT 种子 × RL 种子 0（6 次）；
  - 连同 3 次学习率试跑共 45 次（§10 原来是 33 次），估计多 2–4 小时。λ、学习率和检查点的规则不变，R4、R5 的 λ 也按 §6.2 取各自的 β，学习率试跑仍按 §6.2 只跑一组。

### 12.2 修订二：学习率试跑后先看 KL 涨速（2026-11-04）

- 主档检查点要落在 [1, 1.05]，用到的运行里有一次没对齐，主假设就不可检验（§1）。§6.2 粗查每 100 步一次、到 0.85 才转细查，所以两次粗查之间涨超过 0.2，或者两次细查之间涨超过 0.05，都可能一步跳过这个区间。
- 学习率试跑之后、正式 RL 之前，先看选定学习率下的 KL 记录（试跑只有 KL，不含任何价值）。任何 100 步里涨幅超过 0.1，就按这个涨速把检查改密，使一次粗查的涨幅不超过 0.1、一次细查不超过 0.025（都留一半余量），把新间隔追加进本节，再开跑正式 RL。只改间隔，其他规则不变。没超过就照 §6.2。
