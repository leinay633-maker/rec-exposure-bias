## 3. 候选池与时间分布

- 7,583 个视频的上传日期都在 2022-04-09 至 04-11，所以随机池是这三天上传的新视频，不代表全站内容。其中 NORMAL 7,506 个、AD 76 个、UNKNOWN 1 个。
- 常规日志随视频变老而减少：训练期 4/10–4/12 每天 17 万–28 万行，到 4/18 以后每天约 2 万行，测试期每天 1.3 万–2.1 万行。
- 随机曝光的强度逐日上升：4/23–4/28 每天约 4.1 万–5.2 万行，5/03 以后每天约 9.7 万–11.5 万行。两份测试集在同一时间窗，视频老化对两边一样，但写结论时要注明测试期的视频已上线 18–29 天。
- 随机日志里每个视频平均出现 156 次，p10 是 140、p90 是 179，主体接近均匀。但变异系数 0.197 高于均匀抽样应有的 0.080，原因是有一个低频尾巴（p01 是 3、最少 1 次），可能是部分视频中途退出了候选池。所以只能说“近似均匀”。

## 4. tab 与标签

- 随机日志 98.9%–99.5% 在 tab 1，其余是零星的 tab 2、11、14。常规日志的 tab 1 占 73%–77%，另有 tab 0（8%–13%）、tab 4（约 6%）、tab 6（3%–5%）、tab 2（约 3%）等。
- 在测试期，tab 1 的常规日志有 130,841 行，随机日志有 892,896 行；其他 tab 在随机日志里每个不到 4,000 行。
- 各 tab 的正样本率差别很大（训练期 `is_click`：tab 0 是 9%，tab 1 是 53%，tab 4 是 62%，tab 11 和 14 是 0），不能跨 tab 混着评。
- 用 README 的公式核对（训练期，tab 1）：`is_click` 和“有效播放”（看满 7 秒，或看完不超过 7 秒的视频）一致 96.8%，`long_view` 和“看满 18 秒或看完”一致 97.8%。验证期和随机校准期的 tab 1 也分别在 97% 和 96.7% 左右。所以 tab 1 记录的 `is_click` 近似于有效播放（约 97% 一致，不是严格相等）。另有旁证：README 没给 tab 编号和界面的对应，但作者在 KuaiRand 的 issue #3 里说“值最多的就是单列数据，值第二多的就是双列数据”，而 tab 1 正是两份日志里最多的。
- tab 1 的正样本率：

| 标签 | 训练 | 验证 | 随机校准 |
| --- | ---: | ---: | ---: |
| `is_click` | 0.530 | 0.502 | 0.169 |
| `long_view` | 0.386 | 0.356 | 0.081 |

  全部 tab 合起来，`is_like` 在常规日志是 1.8%–1.9%，在随机校准集是 0.47%。

## 5. 重复行与重叠

- 按（用户、视频、`time_ms`）重复的组：训练 16,514 组、验证 2,710 组、随机校准 3 组。其中反馈不一致的只有训练 10 组、验证 2 组，其余都是整行完全相同。测试期只能按元数据列数，常规测试有 3,869 行完全重复。
- 用户重叠：验证、随机校准、常规测试、随机测试里，分别有 98.1%、97.6%、96.8%、96.1% 的用户在训练期出现过；按行算分别是 98.4%、98.6%、96.4%、97.0%。19:03 那次审计把按行的比例误记成了按用户，19:35 重跑已更正，输出在 `.runs/audit/20261030-193536/`。
- 视频重叠：上述四个切分里，视频在训练期出现过的行占比在 99.4% 以上。
- 每个用户的行数中位数：常规验证 4、随机校准 6、常规测试 5、随机测试 18。

测试期 tab 1 两份日志都出现过的用户有 21,795 个，测试窗口也更长（10 天对 7 天）、随机曝光更多，所以测试期符合条件的共同用户预计多于上表。

## 7. 据此定下的取舍（写进预注册）

- 评测只在 tab 1 做，因为只有它在两份测试集里都有足量数据，界面相同，标签含义一致。训练用常规训练期的全部 tab，tab 作为特征。
- 主标签用记录的 `is_click`（tab 1 里近似有效播放），第二标签用 `long_view`。`is_like` 太稀，共同用户只有约 150 个，不作评测标签，只作 MMoE 的辅助任务。
- 去重规则：整行完全相同的只留一行。之后若（用户、视频、`time_ms`）相同的组还剩多行，说明反馈或元数据有一列不同，整组删掉。测试集打开时用同一规则。
- 用户画像的采集时间 README 没写。活跃度、低活跃期、关注数、粉丝数、好友数可能是 4/21 之后的快照，所以不用。其余画像字段（是否主播、是否作者、注册天数分档、18 个加密特征）作为已声明的风险保留。
- 两份测试集比较时，只用两边都既有正样本又有负样本的同一批用户，每个用户权重相同。各自用自己的用户和曝光数加权算出的 GAUC 只作次要报告。
